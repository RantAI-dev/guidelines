# Bench results: port task, 10 November 2026

Task T6: port `priceCart` from TypeScript to Rust. The worker gets the old source, 12 visible
`input => expected` cases, and `bun ts/oracle.ts`, which runs the old code on any case. The grader
runs 367 hidden cases generated by the same oracle: rounding ties with negative amounts, fractional
percentages, `NaN` and infinity, validation order, and 260 random carts.

## The task discriminates

| Solution | Hidden cases matched |
|---|---|
| Unsolved stub | 1 of 367 |
| Naive port (Rust's `f64::round`) | 343 of 367 |
| Reference port (JavaScript rounding emulated) | 367 of 367 |

JavaScript's `Math.round` sends a tie towards +∞, so -0.5 becomes 0. Rust's `f64::round` sends it
away from zero, so -0.5 becomes -1. No visible case has a negative tie.

## Worker runs: interrupted

All three workers ran through one OpenCode Go subscription. It returned "monthly usage limit
reached" during these runs. **None of the three finished, so none is a graded result.**

| Worker | State when the limit hit | Hidden cases matched by the code on disk |
|---|---|---|
| MiniMax M3.1 Flash | `price.rs` written, a scratch test still present, nothing committed | 367 of 367 |
| DeepSeek V4.1 Flash | `price.rs` written, 2,892 oracle cases generated into `cases/extra.txt`, own tests not yet lint-clean, nothing committed | 367 of 367 |
| GLM-5.3 | nothing written | 1 of 367 |

Both partial ports emulate JavaScript rounding and say why in a comment. Neither had passed its own
check yet, and neither wrote a handoff.

## What to take from it

1. The approach works on the two workers that got far enough: with the old code as the
   specification and an oracle to ask, both found the rounding difference without being told.
2. One subscription for every worker is one point of failure. It stopped all three at once. The
   earlier results file recorded the same thing for a different plan on the first task of the day.
3. A bench costs quota. The runs on this date used roughly fifty worker sessions. Budget for it,
   and run it early in the billing month.

Re-run T6 to completion, three times per worker, before quoting any of this as a result.
